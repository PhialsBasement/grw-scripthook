# Porting to the 2026-09-15 title update (Steam build 25120584)

The 2026-09-15 update rebuilt and re-linked GRW.exe, moving every
native address this hook targets. This change set retargets all of
them and fixes the two engine-concurrency changes the update introduced.

## Offsets

All 101 `SH_IMG` sites across the framework sources were relocated from
the pre-update executable (build 24669148), which was preserved as the
diff ground truth. Method: capstone masked-pattern relocation from each
known instruction boundary (branch displacements and rip-relative
operands wildcarded), with every candidate re-disassembled and compared
instruction-by-instruction against the old body — a match must be
identical modulo absolute addresses, not merely byte-similar.

Two things the update's build does that make naive matching dangerous:

- Most engine entry points are `e9` thunk stubs hopping through a
  one-instruction transform stub (`mov rcx,[rcx+X]; jmp`) to a body
  placed adjacent to the thunk. Only the final body comparison proves
  the pick. The UI colour setter has a near-identical twin that stores
  a different slot; picking it renders every widget default-white.
- Several regions are VMProtect-mutated; comparison always stops at
  the first `ret`, since filler after it differs per build and carries
  no information.

`PLAYER_TF_VTABLE` (test_plugin) was relocated by structure: its
sixteen-slot layout, including three shared stub slots and one repeated
pair, matches the new table at 0x39EA8B8 member for member.

## Concurrency

The update moved physics ray casting and scene rendering onto worker
threads, so callbacks that used to run on one game thread now overlap:

- The ray callback's single-slot queue drain is claimed with an
  interlocked compare-exchange; two workers executing the same job
  raced the done/ret handshake and double-executed plugin requests.
- `ShSceneTick` takes a claim so only one worker ticks the scenes.
- The spawn and NPC pumps take their pending slots atomically
  (`InterlockedExchange64`) instead of clear-after-read.
- Child-array publication in the UI is now lock-free safe by
  construction: the engine's walks read the array pointer and count as
  two separate loads, so every array carries one slack slot pointing at
  a never-attached sentinel label, growth publishes the array before
  the counts, shrink publishes the counts first, and retired arrays
  are leaked (bounded by menu rebuilds) because freeing them raced the
  walks. Live-scene widgets are likewise retired, not destroyed.
  Per-object engine locks are not usable here: only the scene object
  carries an initialized critical section at +0x370.

## Verification

Every relocated address was re-verified against the pre-update
executable by deterministic comparison (code sites and vtable members
instruction-identical; data globals audited by independently
relocating their accessors and requiring a rip-reference to the voted
address): 0 unexplained mismatches across all sites. The same value
set has been running in the maintained fork of this hook in daily
in-game use on build 25120584.
